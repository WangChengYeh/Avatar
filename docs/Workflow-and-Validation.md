## 輸入照片

每張須可解碼為 2048 × 2048 JPEG。四個環各 8 張，加一張俯視圖，共 33 張。每個環使用 `000`、`045`、`090`、`135`、`180`、`225`、`270`、`315` 八個角度。主環可加描述後綴，`01_` 保留給 0°。

| 組別 | 張數 | 檔名範例 |
| --- | ---: | --- |
| 水平全身 | 8 | `01_000deg_front.jpg`、`02_045deg.jpg` |
| 俯角 30° 全身 | 8 | `el30_000deg.jpg` |
| 水平頭部特寫 | 8 | `head_000deg.jpg` |
| 仰角 20° 全身 | 8 | `low20_000deg.jpg` |
| 正上方 | 1 | `top.jpg` |

檔名、JPEG 內容、尺寸、重複角度和相同像素會在輪廓檢查前驗證。頭部近似複製可用 `*_head_review.png` 複核。生圖時固定相機高度、曝光、白平衡與柔光設定，斜角視圖維持正交投影與相同人物比例。33 張都要是 AI 畫出來的同一個人：不能用外殼、重建模型或其他照片渲染／投影產生（AI 修圖單的綠線是輪廓上限，不是要填滿的形狀）。相機與人物中心的距離固定：全身圖（水平、俯角、仰角、俯視）同一構圖，畫面寬 1.95 m；頭部特寫同一構圖，放大為全身圖的 4 倍（畫面寬約 0.49 m）。具體構圖與提示詞見下節「生圖規格」。理由見 [Loop engineering 的理論基礎](Loop-Engineering-Theory.md)。

## 生圖規格

相機繞著人物轉，只改角度，距離與對準點不變（理由見 [Loop engineering 的理論基礎](Loop-Engineering-Theory.md)）。生成後用 `check_turnaround.py` 檢查：第 10d 項量距離，第 10e 項量對準點與俯仰角，第 6c 項粗篩光線，第 10f 項驗收共同表面亮度。成品是無光照 GLB，明暗應由 3D 軟體的燈光產生，不要畫進照片；光源跟著相機轉時，同一塊皮膚在不同角度亮度不同，烘焙後會有色差接縫。

| 組別 | 相機 | 構圖（2048 × 2048） |
| --- | --- | --- |
| 水平、俯角 30°、仰角 20°、俯視 | 全身圖共用同一個 3D 身體中心，距離全部相同 | 畫面寬 1.95 m。水平環人物高約佔 85%（1.65 / 1.95 = 84.6%），頭頂和腳底各留約 7.7%，左右置中。同角度的三個環人物左右寬度相同，俯視圖與正面同寬 |
| 光線（全部 33 張） | 光線固定在人身上，不跟著相機轉 | 全方位均勻柔光，沒有方向性明暗、硬陰影與高光，盡量接近皮膚／衣服本身的顏色；曝光與白平衡固定。同一塊皮膚從任何角度看一樣亮 |
| 頭部特寫 | 對準頭部中心（旋轉軸上、頭頂下半個頭高，約 12.8 cm；頭頂離上緣約 24%），8 張相同；距離全部相同 | 全身圖的 4 倍放大，畫面寬約 0.49 m，頭寬約佔三分之一。頭頂在每張的同一高度（對準頭部中心時離上緣約 24%） |

每張都加上光線提示詞：

```text
even all-round soft light fixed to the subject, no directional shading, flat albedo-like colours,
fixed exposure and white balance across all views, the same skin and clothing brightness from every angle,
no hard shadows or highlights
```

全身圖每張再加上：

```text
same camera distance and framing in every full-body view, only the camera angle changes,
aim at the same 3D body centre, halfway up the figure on the vertical rotation axis,
place that point at the image centre; for the level ring the figure fills about 85 % of the image height,
orthographic projection, 200mm telephoto lens, camera very far away, no perspective distortion
```

頭部特寫每張加上：

```text
head close-up at 4x the full-body zoom, same camera distance in every close-up,
camera aimed at the centre of the head, head width about one third of the image width,
head top at the same height in every close-up, orthographic projection, no perspective distortion
```

其他要求（同一角色、固定種子、相機角度寫法、光線提示詞）見 `python body3d/check_turnaround.py --help` 列出的第九節。

## 18 步重建

| 階段 | `--from`／`--only` 可用的步驟 |
| --- | --- |
| 輸入與相機 | `check` → `cams` → `refine` |
| 幾何 | `arms` → `round` → `legs` → `mesh` |
| 頭部 | `headreg` → `face` → `face3d` |
| 貼圖與匯出 | `uv` → `bake` → `export` |
| 骨架與驗證 | `joints` → `rig` → `unlit` → `verify` → `fit` |

例：已有完整中間檔，修改骨架匯出後可從 `rig` 重新輸出並驗證。調查 UV 問題可單獨重跑 `uv`。

```sh
python body3d/run_all.py ./photos ./output --from rig --name body
python body3d/run_all.py ./photos ./output --only uv
```

預設貼圖解析度為 4096 × 4096，可用 `BODY3D_TEX=2048` 跑 2K 診斷。重跑時確認 `work/` 來自同一組照片與相容的上游步驟。

### MakeHuman 模板（`--template makehuman`，選用）

剪影外殼的網格沒有關節拓樸、手指，骨架權重是自動算的，手臂放下時肩膀會變形。`--template makehuman` 從第 11 步起改用 MakeHuman 人體：

1. `mh33.py` 在 `body33s.ply` 上量手腕、膝蓋、腳踝的中心，`mh_prep.py`（Blender）建立女性 MakeHuman 人體與 Mixamo 骨架（52 根骨頭，含手指），把四肢擺到這些點。
2. `mh_fit.py` 把模板擬合到照片：
   - 先把模板撐到外殼的大小（模板是 MakeHuman 預設體型，比多數外殼瘦一圈：luna-v1 每處都在外殼內 7–10 mm）；
   - Laplacian 正則化 ICP 擬合外殼（在外的點強拉、在內的點輕拉，外殼橋接的凹處不拉）；
   - 手做剛體擬合（平移到外殼指尖、旋轉到外殼的手），腳對齊外殼的腳底；
   - 最後用 24 張全身圖的剪影直接修整輪廓（外殼在各視角之間偏胖，模板是通用體型）；
   - 匯出外殼的頭（脖子以上，含 `face33` 的臉部起伏）。
3. `mh_build.py`（Blender）把擬合後的 T-pose 設為靜止姿勢，依 MakeHuman 的關節定義移動骨頭並保留 roll，移除輔助幾何；**頭換成外殼的頭**：在脖子切開、接上外殼的頭、補縫，頭的骨架權重從原本的頭轉移過來；展 UV。MakeHuman 的通用臉試過貼到這個人的臉上（深度、口腔、髮髻），在完美照片上都留下接縫、破洞或碎片；外殼的頭在兩組完美照片上都烘焙得很乾淨。
4. 第 12 步照常烘焙（手部不從沿著手臂看的角度取色）；第 13 步 `mh_export.py` 直接匯出含骨架的 GLB（骨頭名稱沒有 `mixamorig:` 前綴）；第 14、15 步略過；第 18 步 `fit` 用 `body_mh.ply` 驗收。

需要先在 Blender 安裝 MPFB 擴充（MakeHuman for Blender，2.0.18 以上；程式碼 GPL-3，不隨本 repo 散布）。MakeHuman 的人體、骨架與權重是 CC0，成品可商用。

| 量測（完美照片） | 外殼流程 | MakeHuman（body3d 2.18） | MakeHuman（2.17） |
| --- | --- | --- | --- |
| luna-v1 四道關卡 | 0 FAIL／0 WARN | 0 FAIL／0 WARN | 第 4 關 FAIL |
| luna-v1 最終 `fit` | 5.7% | 6.4% | 14.4% |
| synth 最終 `fit` | 5.0% | 5.9% | 9.9% |
| synth 四道關卡 | 0 FAIL／0 WARN | 0 FAIL、第 2 關 1 WARN（右臉頰 P90 22.4／20） | 臉有接縫 |
| 0°–45° 之間的臉 | 乾淨 | 乾淨（外殼的頭） | 接縫、雙下巴、嘴唇重影 |
| 手臂下垂的肩膀 | 肩頭方塊感 | 圓弧自然 | 圓弧自然 |
| 手 | 一塊 | 有手指與手指骨，手指乾淨 | 手指黑、白色塊 |

已知問題：synth 右臉頰的 WARN（外殼流程 18.0）；兩種模板的肩帶附近都有貼圖色塊、兩腿內側有一條暗線（照片與烘焙的問題，不是模板）。預設仍是外殼流程；MakeHuman 跑完四道關卡 0 FAIL 時，和外殼流程一樣可交付。

```sh
python body3d/run_all.py ./photos ./output --name body --template makehuman
```

## 照片初篩

流程共有 4 道關卡：1 照片檢查、2 烘焙前檢查、3 GLB 驗證、4 最終驗收。每道都印 `總結: N 個 FAIL, N 個 WARN, N 個 PASS，共 N 項`，`run_all.py` 最後彙整成驗收總表並寫入 `OUT/gates.json`；有 FAIL 就停，但停下前做出來的東西都在 `OUT/deliver/` 打包成果：通過是好的成果，有 FAIL 或停在該階段時檔名加 `_FAIL`、不能交付（`--force` 繼續做完只供診斷）。處理規則與交付條件見[標準作業流程](SOP.md)。

照片一律要先經 AI 修正才能進入檢查（真實照片也一樣），所以 `check_turnaround.py` 只有一套門檻：完美照片加小餘裕。1.38.0 起沒有 `--mode` 參數。

| 檢查 | 判讀 |
| --- | --- |
| 構圖佔比，第 2 項 | 水平環人物高佔畫面 84.6%（規格身高 / 畫面寬 1.95 m），差 ≤ 2 個百分點通過，> 8 判 FAIL。完美照片 84.2%／86.1%。 |
| 輪廓清晰度與特寫頭頂，第 8b 項 | 人物輪廓的邊緣過渡 ≤ 4.5 px 通過、> 8 px 判 FAIL（完美照片 1.6–3.2 px）。頭部特寫頭頂離上緣 23.7%，差 > 3 個百分點提醒。 |
| 全視角外殼覆蓋與外殼切割，第 10i 項 | 其他項目一次看一張照片，這一項看 24 張全身圖一起雕出的身體。用規格相機（正交、身體中心在畫面中央、同一比例、檔名角度）雕出外殼，量它蓋住每張水平全身圖的比例：≥ 96% 通過、< 93% 失敗（完美照片 ≥ 97.2%）。另量每張俯角／仰角圖切掉水平環外殼的比例：≤ 10% 通過、> 15% 失敗（完美照片 ≤ 6.6%）；切得太少也不行：< 1.5% 報 WARN、< 1% 失敗（「斜角照是外殼形狀」，完美照片每張 ≥ 2.2%），真實的身體從斜角看一定比水平環外殼瘦，幾乎不切代表照片是把外殼填滿或渲染出來的（R31 15 張 0.0–0.2%，手臂成扁平厚板，成品驗收 18.8%）。R17 每項都只到 WARN，一起雕卻把身體切瘦（覆蓋 73–83%，成品比照片小 25–32%）；側面兩張都往臉的方向畫偏時，鏡像對的旋轉軸（第 10e 項）看不出來，這一項看得出來。 |
| 特寫臉部位置，第 11c 項 | 規格相機下，45°／315° 特寫的臉放回同角度全身圖，和全身圖的臉比（眼角、鼻、嘴、下巴、額頭，以 0° 為準）：≤ 3 mm 通過、> 6 mm 失敗。完美照片 ≤ 0.6 mm，R13 8–9 mm。 |
| 頭部朝向，第 11b 項 | 0°／45°／315° 用 MediaPipe 3D 特徵點量臉的轉向（兩頰連線對畫面的角度）。要等於檔名角度：≤ 8° 通過、> 12° 失敗。特寫和同角度全身圖要一致：≤ 4° 通過、> 8° 失敗。完美照片 40–47°，兩者差 ≤ 1°。 |
| 剪影一致性，第 10 項 | 藍色代表照片有、重建形狀未覆蓋的像素。一般視角 ≤ 1% 通過。俯角／仰角 > 2.5% 失敗，其餘水平視角 > 2% 失敗。水平 90°／270° 採 ≤ 3.5% 通過、> 4.5% 失敗（完美照片 270° 為 3.0%）。紅色顯示形狀超出照片的區域。 |
| 透視，第 10b 項 | 依對角視角的兩手指尖中點偏移來估距離。跨視角平均偏移 < 2% 半臂展通過、≥ 4% 失敗。 |
| 輪廓比例，第 10c 項 | 比對俯角／仰角環與同角度主環的手寬／臀寬、頭寬／臀寬。手寬比差 > 6%、頭寬比差 > 12% 只報 WARN（髮髻讓頭寬隨俯仰角改變），透視由第 10b 項判 FAIL。 |
| 相機距離，第 10d 項 | 正交投影下傾角不改變畫面左右座標，同角度的俯角、仰角與水平全身圖人物寬度應相同，俯視圖與 0° 同寬。差異 ≤ 1% 通過、> 2% 失敗。頭部特寫的頭寬應為同角度全身圖的 4 倍，差異 ≤ 2% 通過、> 3% 失敗（側面 90°／270° 只量頭頂下 12 cm，避開伸向鏡頭的手臂；完美照片各角度 −0.2% 至 −0.6%）。下半身寬度另行比對，用來分辨構圖比例與臂展偏差。 |
| 對準點與俯仰角，第 10e 項 | 由相差 180° 的正交剪影求出旋轉軸。置中差 ≤ 5 mm 通過，俯角／仰角差 > 12 mm 失敗，其餘 > 10 mm 失敗。俯角／仰角環的目標仍為 +30°／−20°，角度差 ≤ 2° 通過、> 4° 失敗。側面與下半身尺度偏差超過 2% 的圖略過角度換算。同一環內的對準高度差 ≤ 10 mm 通過、> 25 mm 失敗。旋轉軸和畫面正中央比較（規格：身體中心投在畫面中央）。另逐張量身體中心（離地半個身高）的上下位置，距畫面中央 ≤ 15 mm 通過、> 30 mm 失敗（完美照片最多 11.3 mm）。左右位置只用鏡像對：單張的左右邊界是指尖，手臂畫斜會被誤判成沒對準。 |
| 光線方向，第 6c 項 | 畫面左右亮差 > 6% 提醒複核。不同角度露出的膚色、衣服、褲子和頭髮面積不同，這項量測可能反映材質差。是否有共同表面亮度差由第 10f 項驗收。 |
| 同一表面亮度，第 10f 項 | 把相鄰角度（水平 a／a+45°、俯角與仰角對同角度水平）投影到主環重建形狀的同一批表面點比亮度。中位數差的絕對值 > 3 或 P90 > 18／255 判 WARN；中位數與避開邊界的中位數都 > 6／255 判 FAIL（完美照片 ≤ 0.7）。共同取樣少於 200 點時標記未量測。超標的配對另列避開高反差邊界的結果，供複核回投對位。 |
| 頭部特寫亮度，第 10g 項 | 特寫縮回全身尺度（÷4），對齊頭頂與中線後，和同角度全身圖的頭部比 Lab L。中位數差的絕對值 > 3／255 報 WARN（完美照片 ≤ 0.7；v1240 135° 為 +18）。P90 多為髮型輪廓差，只列參考。 |
| 耳朵位置，第 10h 項 | 45°、90°、135°、225°、270°、315° 特寫縮回全身尺度，和同角度全身圖比對模糊梯度：整個頭部對齊後，耳朵帶（頭頂下 6–14 cm）再位移多少。≤ 3 mm 通過、> 5 mm 失敗。完美照片 0 mm；v1220 45° 為 13 mm（#17 耳部重影的來源之一）。 |
| 曝光與臉頰亮度 | 膚色平均亮度與主環的差異 > 7% 提醒複核。0° 對 45°／315° 的臉頰粗篩比較取樣區的亮度分位數，最大差 ≤ 12/255。完美照片為 6% 與 11/255（每個角度看到的皮膚不同），同一表面的亮度由第 10f 項直接比較。 |
| 分區亮度，第 9b 項 | OpenCV 依去背輪廓、位置與 Lab 色度估計腳、上衣、褲子、頭髮和裸露皮膚，取各區 Lab L 中位數。只比較看到同一表面的照片：俯角／仰角對同角度水平圖，水平主環與頭部特寫對同組其他張的中位數，俯視圖只比頭髮和皮膚。差的絕對值 > 18/255 只報 WARN，不判 FAIL；同一表面的亮度驗收由第 10f 項負責。顏色規則依目前人物的服裝設定，換服裝時多為未量測。完美照片 0 WARN。 |

以 `--region-luma-dir <資料夾>` 輸出每張照片的分區疊圖及 `region_brightness.csv`。疊圖標色依序為腳部米黃、上衣粉紅、褲子藍色、頭髮橙色、皮膚綠色。分區規則適用這組白底、玫瑰色上衣、深色褲子、赤腳的照片。換裝、髮色或背景改變時，先用疊圖複核分區。
| 臉部一致性，第 11 項 | MediaPipe 在三張頭部特寫檢測五官，並比較眼到嘴／臉高、髮高／臉高。扣掉偵測偏差後偏差絕對值 ≤ 4.5% 通過、> 7% 失敗。 |

流程以 `work/check_status.json` 記錄照片檢查是否 0 FAIL（WARN 不影響）。0 FAIL 時，相機角度只能偏離檔名 ±3°，而且相機距離固定：全身圖都用主環由身高算出的縮放，頭部特寫用其 4 倍，全身圖共用旋轉軸上離地半個身高的點（1.65 m 時為 82.5 cm），投影固定於畫面正中央（`BODY3D_RING_LOCK=1／0` 可強制開關）。Three.js 對照預設套用同一個全身對準點，查看原擬合相機時可加 `--fitted-cameras`。各張自由擬合與固定值的差距記在 `work/ring_consistency.json`。只有照片檢查有 FAIL 又用 `--force` 繼續時，才改用較寬的搜尋範圍（±10° / ±16°）。臉部是必要步驟：沒裝 MediaPipe 時 checker 第 11 / 11b 項判 FAIL，face / face3d 步驟直接報錯；找不到臉時兩步也會停下（照片檢查已經 FAIL），只有 `--force` 才繼續。

## 烘焙前驗收與疊圖 KPI

完整流程在烘焙之前用已校準的相機和網格比對 0°、45°、315° 的臉部特寫。可單獨重跑並輸出疊圖：

```sh
python body3d/check_turnaround.py ./photos \
  --head-overlap-work ./output/work \
  --view-overlay-dir ./output/view_overlays
```

| 驗收 | 通過與失敗條件 |
| --- | --- |
| 同一皮膚位置的臉頰亮度差 | 取共同可見點的亮度絕對差 P90。> 20/255 判 WARN（完美照片 13–16）。 |
| 全身照與同角度頭部特寫 | 共同可見區的亮度差 P90 > 35/255 判 WARN（完美照片 20–30，多為髮緣和網格誤差；光線本身由照片檢查第 10f／10g 項量）。共同覆蓋 < 60% 判 FAIL，低於 80% 提醒複核。 |
| 眼、鼻、嘴投影偏移 | 用可見眼鼻點試算整體縮放與平移，再以嘴部驗證。以圖高 1.35% 為複核目標。有至少 3 個可見點的部位，校正後中位偏移 > 圖高 2% 時失敗（完美照片最多 1.15%）。 |
| 五官尺寸與回投眼距 | 只列 INFO 供診斷，不判 WARN／FAIL：完美照片也差到 29%（MediaPipe 讀 3/4 臉的偏差與剪影重建的臉形），分不出照片好壞。左右斜面各取一側可見端點，也可回投到正面估計雙眼中心距。 |

以上門檻用完美合成照片（相機已知）跑完整流程校準（#28）：照片檢查通過時相機角度就是檔名角度，不再由剪影或 MediaPipe 微調；原本的微調在完美照片上把 45° 全身轉到 48°、45° 特寫轉到 41.9°，臉部因此錯開約 12 mm。完美照片跑完 18 步，四個階段的成果都是好的。

資料不足時，日誌會提示缺少特徵點或有效取樣。`view_overlays/` 把身體與頭部照片各自回投到正面及背面，每列包含參考、回投、50/50 疊圖與亮度差圖。灰底或淡化區域沒有共同可見的取樣。

`view_overlap.csv` 列出覆蓋率、亮度差中位數／P90、亮度差 ≤ 20/255 的比例。覆蓋率 < 5% 時，亮度欄留空。適用的斜面列另有眼、鼻、嘴校正後的中位偏移，以及兩張斜面合計的回投眼距。覆蓋率、亮度和對位各有狀態，疊圖 KPI 供複核，烘焙的退出碼由專用驗收檢查決定。

## 成品與原圖的最終驗收

第 18 步 `fit` 把成品網格用最終相機投影回 24 張全身原圖（`fit_report.py --accept`），量每張的剪影不一致比例，結果存在 `output/fit_report.json`。平均 ≤ 8% 通過、> 10% 失敗（流程停止、結束碼 1，成果打包成 `_FAIL.zip`），單張 > 12% 另列 WARN。門檻依相機已知的完美合成照片校準：平均 5.6–6.6%，單張最高 9.3%。單張偏高時，先看那張照片在第 10、10d、10e 項的結果。
