# 未通過時的診斷 SOP 與診斷樹

[返回 SOP](SOP.md) · [流程與驗收](Workflow-and-Validation.md)

**一句話：FAIL 不用猜，沿著診斷樹問到原因；多個 FAIL 時，前面階段先修、同階段信心高的先修；在問題所屬的階段補檢查、在那個階段裡修；照片就叫 AI 修圖。**

## 診斷 SOP

### 第 1 步：讀診斷

關卡 1、關卡 2 未通過時，`run_all.py` 自動跑診斷（`body3d/diagnose.py`）。每一個未通過項目沿著診斷樹問到葉子，葉子寫明：

| 欄位 | 內容 |
| --- | --- |
| 原因所在的階段 | 問題**發生**在哪個階段（不是被哪一關抓到）：照片是階段 1，重建程式是階段 2… |
| 原因 | 這一項為什麼沒過 |
| 誰要修 | **照片**（AI 生圖：重畫哪一張、怎麼畫）或 **程式**（AI 改程式：哪一步） |
| 信心 | 高：量測解釋得了、數字對得上；中：分支有根據但沒有量測對上；低：沒有對應的規則或量不到 |
| 路徑 | 從關卡到葉子問過的每一個問題，以及當時量到的數字 |
| 順序 | 該先修哪一項（見第 2 步） |

在哪裡看：客戶頁紅框「要修的項目」（第一項標「先修這一項」）、終端機的「診斷 1、2、3…」、`OUT/diagnosis.json`、該階段 `_FAIL.zip` 的 `manifest.json`（`diagnosis`）。單獨執行：

```sh
python body3d/diagnose.py photos  PHOTOS OUT        # 關卡 1
python body3d/diagnose.py prebake PHOTOS OUT/work   # 關卡 2（需要重建中間檔）
```

### 第 2 步：多個 FAIL 時排順序

1. **前面階段的先修。** 後面的階段建在前面的結果上：照片（階段 1）修好，重建（階段 2）的問題可能跟著變、甚至消失。先修後面的，前面一改就白做。
2. **同一個階段，信心高的先修。** 信心高 = 量測解釋得了，修了就知道會不會好；信心低的等高的修完、重跑之後再看，常常已經不見或變清楚。
3. **一次修一個階段**：這個階段的項目照順序修完，就從頭重跑，再看新的診斷；不要同時修好幾個階段。

`diagnose.py` 已照這個規則排好（`order`）。例：R14 的烘焙前檢查有三個葉子，照片的上下偏移（階段 1，信心高）排在重建的特寫環對準點（階段 2，信心高）前面。

### 第 3 步：在問題所屬的階段補檢查

被哪一關抓到 ≠ 在哪個階段發生。問題如果是在前面的階段發生、卻到後面才被抓到，先**改前面那個階段的檢查，讓它會 FAIL**：

- 用出問題的那組照片驗證：新的檢查會 FAIL。
- 用兩組完美照片（Luna 與舊測試模型）驗證：仍然 0 FAIL／0 WARN。
- 照片其實不夠好、照片檢查卻沒抓到 → 這一步就是**補照片檢查**，補好再叫 AI 生圖。

這樣同一個問題下次就在它發生的階段被擋下，不用等到後面才發現。

### 第 4 步：在那個階段裡修

| 原因所在 | 怎麼修 | 修好的標準 |
| --- | --- | --- |
| 階段 1 照片（AI 生的） | **叫 AI 修圖**：把 `ai_fix_request/`（AI 修圖單、要修的原圖、參考圖：特寫是「應該的樣子」，俯角／仰角圖是「輪廓上限」）交給 AI，照單重畫那幾張，放進新的照片資料夾 | 照片檢查 0 FAIL |
| 階段 2–4 程式 | **叫 AI 改程式**：把 `ai_code_request/`（AI 改 code 單：原因、數字、要補的檢查、要改的檔、驗收方式，附 diagnosis.json、gates.json、run_all.log）交給 AI 寫程式，修那個階段、開 PR | 第 3 步的檢查通過，而且兩組完美照片四道關卡仍全部通過 |

人只準備輸入與 token；修圖、改程式都由 AI 做。不能手動補（例如手動平移某張特寫的相機、改中間檔）：那樣的結果無法重現，也不能交付。自動修正只用經過證明的修正（見[自動修正的條件](#自動修正的條件)）。

### 第 5 步：從頭重跑、看新的診斷

用新的輸出資料夾從頭跑。還有 FAIL 就回第 1 步：新的診斷照新的結果排順序。全部通過才往下看[交付條件](SOP.md#可以交付了嗎)。

### 第 6 步：處理不掉就發 issue

診斷信心低或沒有規則、同一個 FAIL 修了 2 輪還在、後面才 FAIL 但前面沒有檢查抓得到、程式出錯或改 code 單做不完、SOP 矛盾、懷疑門檻錯：執行者（ChatGPT／Gemini）用 `body3d/escalate.py` 整理證據，發 GitHub issue 給 Claude，等 Claude 改好 SOP／程式再 pull、從頭重跑（[專案迴圈](Project-Loop.md#什麼時候發-issue任何一條就發)）。

### 例：R14

| 順序 | 葉子 | 原因所在 | 第 3 步：補的檢查 | 第 4 步：修 |
| --- | --- | --- | --- | --- |
| 1 | 45° / 315° 特寫的臉上下位置不同（信心高） | 階段 1 照片 | 照片檢查第 11c 項本來就會 FAIL（8.9 / 7.8 mm；完美照片 ≤ 0.6 mm） | AI 修圖單：head_045deg、head_315deg，附「應該的樣子」 |
| 2 | 特寫相機環的對準點被擬合到旋轉軸前 21 mm（信心高） | 階段 2 重建（headreg） | 烘焙前檢查新增「頭部特寫環對準點」：R14 21.5 mm FAIL，完美照片 0.7 / 1.0 mm PASS | headreg 在照片通過時把對準點固定在旋轉軸上：0.0 mm PASS，45° / 315° 左右偏移回到基準；完美照片仍全部通過 |

R14 的照片檢查有 FAIL，所以流程停在階段 1，先出 AI 修圖單；第 2 項是用對照實驗（相機鎖在規格、`--force`）找出來並先修好的，照片修好後重跑時就不會再出現。

# 診斷樹

## 關卡 1 照片檢查：依項目分類

照片檢查的每一項都直接量照片，所以葉子一律是「照片」，依項目給重畫方式：

| 項目 | 原因 | 怎麼修 |
| --- | --- | --- |
| 斜角照是外殼形狀（10i） | 俯角／仰角照片的手臂幾乎不切水平環外殼（< 2%；完美照片 ≥ 7.7%）：照片是把綠線填滿、或從外殼／重建模型渲染出來的，不是畫出來的人（R31：手臂成扁平厚板，成品驗收 18.8%） | AI 重新生成這張，不能用渲染或投影：真實的俯角／仰角視角，人物在綠線以內、比綠線瘦 |
| 斜角照手臂（10i） | 這張斜角照的手臂和水平環的手臂不一樣（抬的高度、前後角度或長短）：手臂只用正面與俯視照重建，這張的手臂貼圖會貼錯 | 重畫這張，只改手臂，畫在「手臂位置」參考圖的橘色裡（重建用正面與俯視照建出的手臂，從這個角度看的位置）：從斜上方看，伸向鏡頭的手臂在畫面上往手的方向斜向下、比肩膀低（R47 el30_315 畫得太高） |
| 全視角外殼覆蓋、外殼切割（10i） | 俯角／仰角的照片和水平環對不上，一起雕會把身體切瘦 | 重畫切最多的那幾張（照片名稱寫在項目裡），附「輪廓上限」參考圖：水平環雕出的外殼從這個角度看的輪廓（綠線）；人物在綠線以內、比綠線瘦，不是貼滿綠線 |
| 剪影（10） | 這張的人物輪廓超出其他照片推出的身體（藍色）：手臂姿勢、身形或透視和水平環不同 | 重畫這張：同一姿勢、同一身形、正交投影；藍色落在哪個部位就修那裡 |
| 鏡像重合度、左右厚度、腳踝（5、7、7c） | 不同角度看到的身體形狀不一致 | 重畫差最多的那一張：同一身形、同一姿勢 |
| 大小一致、人物高度、頭頂／腳底位置、構圖佔比 | 各張人物大小或上下位置不同 | 所有全身圖同一相機距離與構圖 |
| 輪廓清晰度（8b）、灰白雜點、俯視與主環一致性 | 邊緣模糊、AI 留下的色塊、俯視圖對不上 | 重新生成（原解析度）、修掉色塊、重畫俯視圖 |
| 特寫臉部位置（11c） | 特寫的臉和同角度全身圖的位置不同 | 重畫特寫：同角度全身圖頭部的 4 倍放大，五官位置一致 |
| 頭部朝向（11b） | 臉的轉向和檔名角度不同 | 重畫：頭朝正前方，只有相機繞著轉 |
| 角度（4） | 雙手展開寬度推算的角度不對 | 重畫這個角度 |
| 耳朵（10h） | 特寫的耳朵和全身圖不同 | 重畫特寫 |
| 亮度、明暗、光線（6c、10f…） | 光線跟著相機轉或亮度不同 | 重畫：光線固定在人身上 |
| 距離、放大倍率（10d） | 相機距離／構圖不同 | 重畫：同一距離，特寫固定 4 倍 |
| 對準、頭頂位置（10e） | 沒有對準規格的點 | 重畫：身體中心（特寫的頭部中心）在畫面正中央 |
| 俯仰角、透視（10b、10e） | 俯仰角或透視不對 | 重畫：正交投影、俯角 30°／仰角 20° |
| 翻轉（6b） | 左右翻轉複製 | 重畫 |
| 臉部比例、髮高（11） | 臉的比例和正面不同 | 重畫特寫 |
| 其他 | 沒有對應的規則（信心低） | 依報告「→」後面的建議重畫，並補規則 |

## 關卡 2 烘焙前檢查：全身／頭部臉部一致性（量測分支）

這一項把特寫的五官沿著特寫相機打到重建的頭部網格上，再用全身相機投影回全身照，和全身照裡偵測到的五官比。所以它同時受**照片**、**相機**、**網格深度**影響，要分開問。相機是水平、正交的，因此：

- **上下偏移（dy）** 不受深度影響：網格前後再怎麼錯，水平相機看到的高度都一樣。
- **左右偏移（dx）** 在 45°／315° 會因深度錯而出現，而且兩邊方向相反（dx = −sin φ × 深度誤差）；0° 不受影響。

偏移都扣掉偵測偏差（全身照放大 4 倍裁切 vs 特寫的偵測差）。兩組完美照片校準：dx −1.6…+1.3 px、dy −3.6…−5.9 px，所以基準取 dx 0、dy −5 px，超過 4 px（全身照像素，約 4 mm）才算偏。

```
全身／頭部一致性 未通過
│
├─ 1. 0° 也偏（扣掉基準 > 4 px）？
│     是 → 全部角度一起偏：相機（對準點、比例）或五官偵測 ─────────────► 程式（信心中）
│
├─ 2. 左右偏移：45° 與 315° 反向、反對稱部分 > 4 px？
│     是 → 量頭部特寫環的對準點 z（由 45°／315° 特寫相機算出；完美照片 ±1 mm；烘焙前檢查也有這一項）
│           ├─ 2a. |z| > 5 mm，且 z × sin45° 預測的偏移和實測差 < 35%
│           │       → 特寫相機環的對準點被擬合到旋轉軸前後 ───────────► 程式（信心高）
│           │         怎麼修：已修（headreg 1.40：照片通過時對準點固定在旋轉軸上）；再出現表示照片沒通過或程式退步
│           └─ 2b. 對不上 → 臉部網格的前後深度不對 ───────────────────► 程式（信心中）
│
└─ 3. 上下偏移：45° 或 315° 相對 0° > 4 px？
      是 → 看照片第 11c 項（規格相機下，特寫的臉放回全身圖）的上下差
            ├─ 3a. 同方向、且至少 40% → 特寫的臉和全身圖上下位置不同 ─────► 照片（信心高）
            │       怎麼修：重畫該張特寫
            └─ 3b. 照片沒量到 → 特寫相機的上下對準或比例 ─────────────────► 程式（信心中）
```

### 這棵樹的根據（R14 對照實驗）

照片相同、只差兩張特寫，相機都鎖在規格（`BODY3D_MAX_DPHI=0 BODY3D_MAX_DTH=3 BODY3D_RING_LOCK=1`，`--force --no-autofix`）：

| 實驗 | 0° dx / dy | 45° dx / dy | 315° dx / dy | 特寫環對準點 z | 烘焙前檢查 FAIL |
| --- | --- | --- | --- | --- | --- |
| Luna 完美照片 | −1.1 / −4.3 | −1.5 / −5.0 | −0.8 / −5.3 | +0.3 mm | 0 |
| 舊完美照片 | −0.3 / −5.5 | +1.1 / −4.8 | −0.3 / −5.3 | −1.0 mm | 0 |
| A：R14 原照片 | −3.1 / −3.9 | −21.3 / −18.1 | +10.5 / −10.2 | +21.4 mm | 9 |
| B：A＋特寫平移（11c 自動修正） | −2.2 / −6.5 | −24.4 / −12.6 | +13.5 / −4.8 | +21.4 mm | 8 |
| A＋特寫環對準點移回旋轉軸 | −3.1 / −3.9 | **−4.2** / −18.4 | **−5.4** / −10.0 | 0 | 10 |
| A 用修好的 headreg 重建 | −2.3 / −3.4 | **−4.6** / −17.9 | **−4.8** / −9.5 | 0.0 mm | 8（全是上下：照片） |

（全身照像素，三個五官的中位數；1050 px/m。）

- **左右**：A 的反對稱偏移 −15.5 px，由對準點 z = +21.4 mm 預測 −15.9 px，對得上（2a）。把對準點移回旋轉軸、其他都不變，45°／315° 的 dx 回到和 0° 一樣（−5 px）。照片第 11c 項量到的左右差只有 1.6 mm：左右這部分**是程式**（headreg 用剪影擬合特寫相機，頭髮、髮髻把對準點拉到前面）。
- **上下**：照片第 11c 項量到 45° −8.8 mm、315° −7.6 mm，和重建後的上下偏移同方向（3a）：上下這部分**是照片**。
- **11c 的自動平移只修得了一部分**：B 的上下偏移只改善 5–6 px，因為特寫環的上下對準由 8 張共用，平移其中兩張會被整個環吸收約四分之一；照片檢查通過了，烘焙前檢查還是未通過。所以 11c 不啟用自動修正（`autofix.py` 的 `PROVEN` 是空的），一律交給 AI 重畫。

## 自動修正的條件

一個修正要在對照實驗（同一組照片，只差被修的幾張）裡，讓**後面的關卡**變好，才放進 `autofix.py` 的 `PROVEN`。只讓照片檢查自己通過不夠：照片檢查通過、後面才失敗，會讓階段 1 的結果包被誤標成好的。目前沒有經過證明的修正。

## 關卡 4：成品剪影（最終驗收 FAIL）

成品投影回 24 張全身照，平均不一致 > 10% 時（`diagnose_fit`，讀 `fit_report.json`）：外殼由全部照片一起雕，一張和其他角度對不上的照片會把別的角度看得到的身體切掉，所以不一致最大的照片就是要重畫的照片（照片，信心中）。

- 修圖單列不一致最大的 6 張（單張 > 12%），其餘超過的只寫張數：先修這幾張，重跑後再看。
- 每張的方向看多出／缺少的像素：模型超出照片（照片畫得瘦、小或偏）、照片有模型沒有的部分（畫得胖、大，或手腳位置不同），或兩者差不多（位置、姿勢、比例對不上）。
- 斜 45° 的角度在每一環都最差時，第一項註明斜角環和水平環對不上；斜角照附「輪廓上限」參考圖，照水平環畫。
- 這片葉是照片的問題，所以「後面才 FAIL、前面沒抓到」不再直接發 issue，先照修圖單重畫（R54：前三關都過、第 4 關 15.4%，原本沒有修圖單就發 issue）。照片檢查沒抓到這些照片仍是缺口，由 Claude 另外補。

## 還沒有量測分支的項目

關卡 2 的其他項目（頭部相機角度、頭部重疊區亮度、正面／斜面一致性）、關卡 3（GLB 驗證：程式）目前沒有量測分支；它們的未通過照舊列在「要修的項目」，依[SOP](SOP.md#停下來時怎麼辦)判斷。有對照實驗的數據後再加分支。
